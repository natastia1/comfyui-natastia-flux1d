# natastia-flux1d
ComfyUI workflow Dockerized via [comfyui-wizard](https://comfy.getrunpod.io).
Submission: https://comfy.getrunpod.io/dashboard/submissions/kd71xeam8smcw6dfn0jer203bs8cx5tc
## Build it yourself
```bash
docker build -t my-comfy-workflow .
docker run --rm --gpus all -p 8188:8188 my-comfy-workflow
```
If the workflow uses gated HuggingFace or CivitAI models, pass tokens at build time:
```bash
docker build --build-arg HF_TOKEN=$HF_TOKEN --build-arg CIVITAI_API_KEY=$CIVITAI_API_KEY -t my-comfy-workflow .
```
## Deploy on Runpod
1. Connect this repository at https://runpod.io/console/serverless
2. Create a new endpoint, select **Deploy from GitHub**
3. Pick this repo, branch `main`
4. Runpod's builder will build the Dockerfile and host the resulting image
5. Hit the endpoint with the API workflow JSON (`api-workflow.json` in this repo)
## Files
- `Dockerfile` — generated by comfyui-wizard, fully resolved
- `workflow.json` — the raw workflow, as you designed it in ComfyUI
- `api-workflow.json` — converted to ComfyUI's `/prompt` API shape (use this for serverless)
- `handler.py` — placeholder, not used at runtime (see below)
- `README.md` — this file

## About `handler.py`
This image is built `FROM runpod/worker-comfyui:*-base`, which already bakes in
its own `/handler.py` and `start.sh` that call `runpod.serverless.start()` to
serve ComfyUI as a queue-based Serverless endpoint — that's what actually runs
in the container.

Runpod's "Deploy from GitHub" flow statically scans this repo's source files
for `runpod.serverless.start(` before letting you create the endpoint, and
fails with *"Could not find runpod.serverless.start() in your repo"* if it
doesn't find a match, even though the base image already provides it. The
`handler.py` in this repo exists only to satisfy that scan; it is never copied
into the image or invoked at runtime.
